# 原文忠实度与整组叙事（制作、重做图文均必读）

任务是把指定网页的论证可视化，不是围绕标题另写一篇技术文章。优先级：**原文依据 → 整组逻辑 → 单页讲清 → 可读性 → 版式变化**。后者不能破坏前者。

## 先还原文章，再拆成页面

浏览器读取全文，保存 `data/source.json`：`url`、`title`、`capturedAt`、按出现顺序排列的 `sections[{id,heading,paragraphs[]}]`。段落须为原网页可核对的文本，不得用自己改写的摘要冒充原文快照。

在设计图片前写 `data/narrative-plan.json`：

```json
{
  "goal": "读者读完应能回答的原文核心问题",
  "throughline": "原文为何先讨论甲，再讨论乙，最终如何回答问题",
  "sections": [{"sourceId":"s1","role":"这节在原论证中的作用"}],
  "pages": [{
    "slug":"meaningful-name",
    "sourceIds":["s1"],
    "question":"这一页具体解决什么问题",
    "answer":"原文对这个问题给出的明确答案",
    "fromPrevious":"承接上一页的什么结论、尚未解决什么",
    "toNext":"本页讲完后，为何需要下一页",
    "claims":[{"text":"将出现在图片中的一个实质性主张","sourceId":"s1","quote":"原文连续片段"}]
  }]
}
```

首张讲解卡要交代目标、问题背景和接下来的讲解路线；末页回到同一个问题并收束。按原文章节与段落推进，允许为可读性拆页、合并同一节内容，不能换成通用的术语目录、避坑大全或测评流程。回顾前面章节可以放在末页，标明 `recap: true`。

每页以问题或结论命名，而不是只写一个术语。图中的对象、输入、动作、结果要能被读者认出来；箭头必须表达真实的顺序、依赖、分支或流向，不能只是把概念串起来。开头用一两句交代当前问题如何承接上文，结尾留下明确结果或下一步。章节导航可辅助定位，但不能替代实际解释。

### 内部策划与可见文案分开

`question`、`answer`、`fromPrevious`、`toNext` 是策划字段，不是要印在图片上的栏目。图片与平台正文同样只讲内容本身：结论直接写，不加“本页结论/本页小结”；衔接不写“上一页/下一页/这张图/本图介绍/这一节讲完”等页面导读。用知识关系衔接，例如“KV Cache 减少了重复计算，但并发越高，显存占用越大”，或“接下来，把 KV Cache 按块分配和管理”。不能只把“下一页”换成“接下来介绍本页内容”来绕过要求。

允许技术主题导航和页码帮助定位，但不要把内部策划说明、作图说明或对内容的评价当正文。最后一张直接收束技术结论，不强加后续预告。内部计划可以记录“论证结束”，但不渲染出来。

## 原文依据是硬边界

- 所有实质性事实、机制、数字、案例、方案分支、图形标签与总结都要能回溯到快照段落。图上的关系也属于主张，需要依据；每页 claims 应覆盖整页，不是给整页随便挂一段相关原文。
- 允许忠实改写、拆句和概括；承接语可以解释原文已有的逻辑，但不能借承接语新增技术结论。
- 禁止凭常识或外部资料补工程方案、算法参数、性能数字、压测步骤、风险清单或面试经历。即使技术上正确，没有出现在指定文章中也不能默默加进原文改编。
- 不创造数字案例来填图，不把示意图的节点数、块宽或长度画成实测性能。原文没有数量时用有名称的对象和定性关系表达，不加虚构比例。
- 不为凑页数、三条解释、统一总结框、视觉结构数量增加内容；不凭空加追问、案例或参考回答。原文有参考回答才改编参考回答。
- 原文若有疑似错误、矛盾或过强承诺，在内部审校记录中标出。可以不展示有争议的绝对数字，保留可由原文支持的机制；如果必须改结论才能成立，先告知用户，不暗中用另一篇技术教程替换原文。
- 封面上的企业、轮次、真题出处同样需要来源或用户明确提供的真实背景，不得从“大厂池”随机虚构。没有依据时用中性题型前缀，且不要擅加“模拟”。

## 验收：既核对来源，也从头读一遍

先运行 `node scripts/validate-narrative.mjs <job>`，再人工检查：

1. 对照全文：每个主张及图中关系都得到相应引文支持，未偷换含义、遗漏条件或引入外部知识。
2. 连续阅读：只读各页标题、承接句、结论，能复述完整论证；没有必须自行猜测的跳转。
3. 单页阅读：不看原网页也能说清这页的对象、问题、方法与结果；不认识的术语在首次使用处解释。
   同时检查成图全部可见文字（包括模板注入的标题、页脚和过渡句），没有页面自述或导读标签；不能只搜索原始文案 JSON。
4. 打乱检查：如果任意交换中间页面也不影响理解，说明只在罗列并列概念，要检查是否丢失原文的推进关系。原文自身为并列方案时，应明确共同目标和比较维度，不硬造先后依赖。

把具体检查和残留问题写入 `qa/narrative-review.md`，并按 `quality-gates.md` 的格式记录绑定当前文件版本的 `qa/content-review.json`。原文引用脚本只检查文件、引用存在与次序一致，**不能证明语义正确或逻辑清晰**；总校验仅在自动检查和当前版本审读记录均通过时给出 PASS，不得跳过上述逐页审读。
