# 小红书文案标准

用户手动发布需要标题和正文；**小红书/抖音另提供候选话题，小绿书改用项目文章链接结尾**。基于文章内容生成，调性贴平台，不是把公众号正文搬过来。

## 铁律：不做站外引流
小红书严打外部引流，**正文、标签、图片里都不要出现**：公众号名、微信号、外部网址（含 golangstar.cn）、加群、私信领取等。站内引流只靠内页卡里的品牌导航/目录做曝光，文字层面不碰。违规会限流甚至封号。

这条禁外链规则适用于小红书/抖音文案与跨平台通用图片，不要误用到小绿书按用户指定添加的学习网站和项目入口。小绿书结尾按 [wechat-project-footer.md](wechat-project-footer.md) 先放学习网站介绍文章链接，再放两个项目文章链接，不能追加话题标签。

## 铁律：正文禁用引号
正文里**严禁乱用引号**，包括英文直引号、中文左右引号、单引号、直角引号等。正文乱用引号是 AI 写作最明显的味道之一。
- 不要把普通概念包成引号。比如 会聊天的大模型 这种词，直接裸写。
- 不要用引号制造强调。比如 LLM + Planning + Memory + Tools 这种结构，直接裸写。
- 只有原题、代码符号、函数名、平台字段必须保留时才允许出现在图片或引用材料里；**笔记正文默认零引号**。
- 输出 `copy.md` 后校验正文可见文字：不能匹配 `/["“”‘’「」『』]/`。HTML 链接属性所需的引号不属于正文，不能为通过校验删掉 `href`。

## 标题（封面标题 vs 笔记文字标题字段，两者不同）

**① 封面标题**（图片上的大字，无字数限制）
- 保留**原标题原文**（仅去掉开头序号），自动缩放。
- 企业和轮次只用有来源或用户明确提供的真实背景；禁止随机编造，无依据时使用“大模型面试题”等中性前缀，不擅加“模拟”。

**② 笔记的文字标题字段**（发布页那个有字数上限的标题框，**小红书/抖音/小绿书都 ≤20 字**）
- **不用封面那种长前缀**（字节大模型一面占 8 字太长，会把题挤没）；但**也不要完全去掉前缀**，面试类词天然有热度，全去掉会丢流量。
- **用短前缀 `面试官：`**（4 字）+ 精简后的面试题，凑成 ≤20 字（精简允许改写，因为是硬限制）。
- 例：原题是自注意力机制如何工作、为什么比 RNN 更适合长序列 → 标题字段 `面试官：自注意力为什么强过RNN`（15 字）。
- 三平台用同一个这样的标题即可。（注：小绿书图片消息标题也是 20 字，不是文章那种 64 字。）

## 铁律：每篇正文都要重新写，禁止套模板（最重要）

这是正文质量的生命线。**绝不能**把每篇都套成同一个壳——同样的开头句式、同样的口头禅、同样的编号列表、同样的收尾、同样的句尾 emoji。两篇并排一看就是一个模子刻出来的，读者一眼识破是 AI/营销号批量产的，内容再好也废了。

**怎么做到每篇不同（按这篇文章本身去提炼，而不是往模板里填空）：**
- **先读懂这篇文章独特在哪**：它最反直觉的点、最容易被面试官追问的点、作者讲得最透而全网讲不清的点是什么？正文的钩子和重点，要从**这篇的具体内容**里长出来，不是套通用句式。
- **开头来自原文**：用原文场景、问题或结论开场，不虚构面试官原话、数字、个人踩坑经历。
- **结构换着来**：不是每篇都必须按钩子、编号、收尾来套。有的文章适合编号清单，有的适合三个层次，有的适合先抛结论再拆解，有的适合误区 vs 正解对照。让结构贴合这篇内容的逻辑。
- **收尾落在内容上**：以原文的技术结论自然结束，不强制点赞收藏，不编写“这篇讲完了什么/下一篇介绍什么”等导读或预告。平台固定项目链接按结尾规则追加。
- **emoji 换着用、宁少勿多**：句尾 emoji 是点缀不是公式。不要每篇都固定 😮‍💨👇💪 这三件套；有的篇一个不放也很好。
- **遣词造句口语、有具体信息量**：避免干货满满、一文讲透、建议收藏等空话。数字、事实与对比必须有原文依据，不能为了显得具体而添加量化效果。

判断标准：**把这篇文案和上一篇并排放，如果句式骨架几乎一样，就是失败，重写。**

## 正文写法（原则，不是固定模板）

### 直接讲内容，不介绍这份内容

发布正文应让读者读到原文中的问题、解释和结论，不能写成文章简介或图片目录。可以压缩原文，但保留因果、条件和顺序；不把内容缩成名词清单，也不另加原文没有的工程知识。

禁止“这篇文章介绍了”“这篇做成了 N 张图”“图里讲了什么”“最后附参考答案”“顺着这组图复习”等自我介绍。不要为了区别于参考回答，反而禁止解释概念与机制。

判断一句话是否合格：它是在解释技术问题本身，还是在告诉读者这篇文章/这组图片提供了什么？后者删除或改为有原文依据的实际解释。字数限制允许压缩内容，但不能把正文压成简介、目录或术语列表。

同样适用于图片中的所有可见文字：不加“本页结论/本页小结”，不写“上一页/下一页”。结论直接呈现，过渡用具体内容或“接下来……”。策划字段和页面导航的区别见 `source-narrative.md`；改写后还要检查模板渲染结果。

优先使用有承接关系的自然段；真正的并列方案、对照或执行步骤才用少量列点，不整篇套钩子—三点—收藏模板。结尾落在原文的技术结论，可不做行动号召。

平台结尾仍分开：小红书/抖音提供 8–12 个候选话题；小绿书不带话题，先附 `学习网站：` 与指定介绍文章，再附 `Agent项目：` 与两个指定可点击文章链接。

## 分点标记规范（按平台不同 · 重要）

通用底线：**不要每行换一个不同的花哨 emoji**（如 🧠🔑📐🪢🆚⚠️ 各一行）——乱、显廉价。同一组列表用同一种标记。

### 小红书 & 小绿书（自然段优先，图标可选）
图标和 emoji 仅为可选点缀，不构成内容合格标准。不得为了平台感强加分点，用户要求不加时不加。

给用户的手动发布粘贴稿必须压成**单换行**，不能保留空行：`split(/\n+/).map(trim).filter(Boolean).join('\n')`。小红书/小绿书预览里的空行会被放大成明显断层，正文看起来像没排版。

小绿书正文可以更短，但核心解释须完整并收束到技术结论，不必另外写收藏、复习等动作。

自然收尾之后另起单换行，放学习网站与项目链接结尾，网站链接在两个 Agent 项目上方。`AI模拟面试官` 是项目名称，必须原样保留；它和封面不得擅自添加“模拟”前缀的规则是两回事。

分点标记**候选集**（同一组列表只用其中一种，别每行换）：
- ▶️ 蓝三角：步骤/递进，适合技术链路、方法演进
- ✅ 绿勾：结论/要点，适合 checklist、避坑总结
- 🌿 叶子：开头点缀，一篇 0–1 个
- **阿拉伯数字 `1. 2. 3.`** 仅在有真实步骤或并列关系时使用，不要求搭配 emoji。
- **❌ 不用 ⭕**（不美观，已移出候选集）
- 句尾偶尔点 1 个情绪 emoji（💪、👇）可以，克制。

### 抖音：朴素，纯数字，零图标
分点一律用 `1. 2. 3.`，**不放任何图标/emoji**（连句尾的 😮‍💨👇💪 也不要），整段干净纯文本。
抖音正文文件和手动发布粘贴稿要用**单换行**分隔段落/列表，**不要保留空行**。交付前必须检查没有 `*1.`、`*这题` 这类残留。

这些标记只决定必要列表的写法，不要求正文必须列点、加导读标签或追加收藏口号。小红书/小绿书仍以自然段为默认。

## 输出
写到 job 目录的 `copy.md`，给用户确认后用于手动发布。格式：

```
标题（3 选 1）：
1. ...
2. ...
3. ...

小红书正文：
<多行>

抖音正文：
<多行，纯数字，无 emoji，无空行>

小绿书正文：
<独立正文与自然收尾>
学习网站：
[秀才的进阶之路](https://mp.weixin.qq.com/s/FV93xYRR9R2BCWwKHC1A8A)
Agent项目：
[AI模拟面试官](指定文章链接一)
[DevSupport智能客服系统](指定文章链接二)

小红书/抖音候选标签：#... #... ...
```

`copy.md` 里的 Markdown 方便查看，不代表可直接粘贴成公众号超链接。交付小绿书时另外生成 `wechat-content.html`，三条均使用公众号文章链接标识和真实 `<a href>`；模板及校验规则见结尾说明。
