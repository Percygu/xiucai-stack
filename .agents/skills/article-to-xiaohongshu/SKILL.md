# 网站技术文章 → 小红书 / 抖音 / 小绿书 图文笔记

把一篇技术文章变成一组图文（**封面 1 张 + Claude 原文页 1 张 + 小红书图解讲解卡 N 张，全 1080×1440 / 3:4**）+ 文案，交给用户自己发。

**默认只交付素材，不执行平台操作。仅当用户明确要求更新已有公众号草稿时，按 `references/wechat-project-footer.md` 原位修改并回读验证；这不授权新建草稿或公开发布，也不扩大到其他平台。**

**关键口径：Claude 原版文档页只保留 1 张，作为原文权威/引流卡；其余内页必须重新设计成小红书讲解卡。** 讲解卡不能是浏览器网页截图，也不能是纯 bullet；必须图文并构、形式多样、信息饱满。

## 图片与正文的两条内容要求

1. **图片是原文的图解，不是概念拼盘或页面导读。** 严格依据指定网页，保留目标、论证顺序与前后关系，每页讲清具体问题，不杜撰机制、案例或数字。结论直接呈现，不出现“本页结论”“上一页”“下一页”“这张图介绍”等文字；用内容本身或“接下来……”自然衔接。详细执行与内部策划边界见 `references/source-narrative.md`。
2. **正文是知识内容，不是文章摘要式介绍。** 直接解释原文中的问题、机制、条件与结果，不写“这篇文章介绍了”“图里讲了什么”“最后附参考答案”等话术。优先连贯自然段，真正需要表达步骤、并列或对照时才适度列点，不靠罗列名词代替解释。平台格式与结尾见 `references/copywriting.md`。

以上要求适用于后续每篇制作和修改；验收同时检查实际成图与最终正文，不能只检查策划文件。版式和平台风格不能凌驾于原文忠实度、逻辑和直接讲内容的要求之上。

**强制验收**：交付必须通过 `scripts/validate-job.mjs`。`FAIL`（不合格）或 `REVIEW_REQUIRED`（待审读）都禁止交付；只有自动检查通过且当前产物的逐页/正文审读记录齐全，才输出 `PASS`。具体证据格式、检查范围及修正闭环见 `references/quality-gates.md`。

## 标准（动手前必读对应文件）
- 原文依据与叙事（所有图文任务先读；逐页溯源、原文顺序、前后衔接）→ `references/source-narrative.md`
- 视觉（封面两风格、1 张 Claude 原文页、小红书高质量图解卡、字号、品牌水印）→ `references/visual-standards.md`
- 文案（直接讲内容、自然段与必要列点、平台结尾差异、正文零引号）→ `references/copywriting.md`
- 小绿书结尾（不用话题，学习网站链接在两个 Agent 项目链接之前）→ `references/wechat-project-footer.md`
- 交付（图片位置、文案文件、发布入口链接、自动化禁区）→ `references/publishing.md`
- 抽取（从文章页提取正文+目录+导航）→ `references/extract.md`
- 质量门禁（视觉策划表、版式多样性、尺寸/导航/产物自动校验）→ `references/quality-gates.md`

## 工作流

### 1. 建 job 目录、拷模板
```
mkdir -p ~/小红书/jobs/<slug>/data
cp <skill>/assets/{cover.html,inner.html,explainer.html,serve.mjs,render-cards.mjs} ~/小红书/jobs/<slug>/
```

只能从当前 skill 的 `assets/` 起步。**禁止把上一个 job 的 `explainer.html`、`cards.html`、`cards.json` 直接复制到新 job 再换文案**；旧 job 只能作为内容灵感，不能作为版式模板。`assets/explainer.html` 也只是字号、色板和基础组件的起点，不是一套文章从头用到尾的成品版式。

### 2. 抽取文章 → data/
用 Codex 可用的浏览器自动化打开文章 URL（优先 in-app browser / Playwright），按 `references/extract.md` 提取，生成：
- `data/content.html`：清洗后的正文 HTML。
- `data/meta.json`：标题、作者、标签、顶部导航、左侧完整题库目录、当前篇下标。

`content.html/meta.json` 用于两件事：
1. 渲染 1 张 Claude 原版文档页引流卡。
2. 作为后续小红书讲解卡的内容依据。

不要把整个文章都用 Claude 文档页分页发布；只取第 1 张文档页。

### 3. 先整理原文逻辑，再生成封面文案
按 `references/source-narrative.md` 保存原文段落快照 `data/source.json`，写出目标、论证顺序和逐页来源映射 `data/narrative-plan.json`，再做视觉策划。不能先选版式、再搜集概念填空。

封面保留（仅去序号的）文章原标题，关键词加高亮。公司和轮次必须有原文依据或用户明确提供的真实背景，禁止随机编造；缺少依据时用“大模型面试题”等中性前缀。`brand` 填 `IT杨秀才`。详见 `visual-standards.md`。

不要擅自给封面加“模拟”前缀，也不要改为角标、底部标签或副标题；memo 标签可以用“附参考回答”。保留原题和用户确定的版式，不额外声称已核验企业真题出处。

### 4. 生成内页（1 张原文页 + 多张讲解卡）
1. **第 1 张内页：Claude 原版文档页**
   - 使用 `assets/inner.html` 读取 `data/content.html` 和 `data/meta.json`。
   - 只渲染 `?only=0` 得到第一张文档页，作为原文权威/引流卡。
   - 这张卡保留顶部导航、左侧题库目录、正文样式，沿用 `.claude` 原版。

2. **后续内页：小红书图解讲解卡**
   - 必须把指定原文可视化，允许忠实改写，不用外部知识替换或扩写原文。每页问题、结论、图中关系与解释都要有逐条原文依据。
   - 形式要多样：流程图、树结构、图结构、对比矩阵、工程选型表、Prompt/代码结构图、参考回答卡。
   - 每张卡都要有视觉主图或结构图，不能只有几个空洞点。
   - 顺序沿用当前原文的实际论证，不套通用章节链。首张讲解卡讲目标和路线，每页明确承接关系，末页回答最初问题；原文没有追问、案例、压测或方案分支，就不添加。
   - 按“两条内容要求”检查全部可见文字；内部策划字段不得变成图片标签，详见 `references/source-narrative.md`。
   - **手机端可读性是硬门槛**：讲解卡核心正文/表格不低于 28px（优先 30–32px），辅助说明不低于 24px（优先 26–28px），小标题不低于 34px。内容放不下就拆卡，绝不能靠缩小字号硬塞；完整标准见 `references/visual-standards.md`。

3. **先做视觉策划表，再写 HTML**
   - 基于已审读的叙事计划生成 `data/visual-plan.json`，逐页 slug 和顺序一致，写清核心问题、主图如何回答问题、必要解释和结论。不能为了凑解释块或版式数量增加原文没有的内容。
   - 再根据策划表生成 `data/cards.json`；每个 `pages[]` 项都要提供与策划表一致的语义化 `slug`，供渲染脚本生成可辨认的文件名。
   - 8–15 张讲解卡至少使用 **5 种真正不同的视觉结构**；同一种结构不超过讲解卡总数的 35%，相邻两张不得复用同一版式骨架。
   - `grid2/grid3/list/answer` 只是文字容器，**不算视觉主图**。仅仅换颜色、换边框、把三个框改成四个框，也不算新结构。
   - 至少 60% 的讲解卡必须由流程、关系、层级、路径、选择或对照本身承担主要信息，不能依靠一组文字框撑满页面。

### 5. 生成各平台文案 → copy.md
按 `references/copywriting.md`：
- **文字标题**（≤20 字，三平台通用）=「**面试官：** + 精简题」（如「面试官：自注意力为什么强过RNN」）。
- **正文分平台生成，不能三平台共用同一份**：
  - 小红书/小绿书正文：直接解释原文的内容，优先自然段；只有并列方案或步骤才列点，图标可选，不强制。
  - 抖音正文：纯数字分点，零图标、零 emoji、单换行。
- **正文不是文章导读**：直接讲问题、机制和结果，不写“这篇做了多少张图”“图里讲了什么”“最后附参考回答”等介绍性话术。长文压缩也要保留原文逻辑，不变成术语清单。
- **平台结尾必须分开**：小红书/抖音保留 8–12 个候选话题；小绿书正文不追加 `#话题`，在自然收尾后先追加 `学习网站：` 及用户指定的学习网站介绍文章链接，再追加 `Agent项目：` 和两条项目文章超链接，三个链接均为公众号文章，唯一地址来源见 `references/wechat-project-footer.md`。
- 小红书/抖音文案与通用图片仍不放外部链接；小绿书文末保留上述三条原生文章链接。把 copy.md 给用户确认。

### 6. 渲染卡片（三平台共用）
```
cd ~/小红书/jobs/<slug>
node serve.mjs &                      # 常驻静态服务器(8788)
```
用浏览器自动化分别打开 `http://localhost:8788/inner.html?only=0` 和 `http://localhost:8788/explainer.html?only=0`，确认 `window.__READY__` 为真、首张原文页与讲解卡都能正常显示。然后：
```
node render-cards.mjs random random 8788 random
# 也可指定：node render-cards.mjs memo blue 8788 sky
kill %1
```

渲染脚本使用 Playwright 同时采集成图可见文字、字号、边界与文件指纹，写入 `qa/render-audit.json`。若本地不能直接导入 Playwright，用工作区依赖工具定位模块，再设置 `PLAYWRIGHT_MODULE` 为该模块绝对路径；不要跳过审计改用裸截图。自定义渲染器也必须按质量门禁输出同等证据，建议复用 `scripts/capture-card.mjs`。
产物 `output/`：`00-cover-<风格>-<背景>.png` + `01-origin-doc.png` + `02-<slug>.png` + `03-<slug>.png` …。文件名前缀就是上传顺序，语义化 slug 用于辨认内容。
> Claude 原版 `inner.html` 只用于 `01-origin-doc.png`；讲解卡另用前端程序/SVG/HTML 渲染，不能用 AI 生图写中文。
> 讲解卡必须一篇文章统一一套主题色池，但不同文章随机换主题；不要固定同一浅底、同一黑框、同一组描边色。

渲染后必须逐张做手机端可读性验收：
- 用浏览器读取讲解卡全部可见文本的 computed font-size；核心正文/表格 `<28px`、辅助文字 `<24px`，直接判失败并重排。
- 把成图等比缩到约 360×480 查看；无需放大即可读清正文，且没有重叠、截字、强制断词或被浮层遮挡。
- 三栏及以上布局只承载短标签；只要栏内出现连续解释句，就改成纵向大块或拆页。不要为了维持固定卡片数量压缩字号。
- 任一张不合格都不能交付；修正后重新渲染并复检整套。

交付或进行任何后续平台操作前，必须再运行：
```
node <skill>/scripts/validate-job.mjs ~/小红书/jobs/<slug>
```
只有输出 `PASS`（退出码 0）才能继续。脚本检查原文引用、图片和最终正文、导航、尺寸、字号与成图审计，并验证 `qa/content-review.json` 的逐页/正文审读是否覆盖当前文件版本，输出 `qa/validation-report.json`。缺失证据或检查失败必须修正，未审读或审读过期必须复核；原文忠实度、清晰度和逻辑不能靠关键词或脚本证明，不得自动填满审读记录来换取 PASS。

### 7. 告诉用户图片、文案和发布链接（见 `references/publishing.md`）
**平台可任选其一或任意组合**——三平台相互独立。卡片只渲染一次通用；文案按所选平台的风格生成。用户说"只做小红书""只做小绿书""小红书+抖音都做"都照办，不要默认三个一起做。
- 整理 `output/` 图片顺序：按文件名前缀从 `00` 开始上传。
- 整理 `copy.md`：标题、小红书正文、抖音正文、小绿书正文、候选标签。
- 最终回复只告诉用户三件事：图片目录/首图顺序、文案文件路径、发布入口链接。
- **默认到这里结束；用户明确要求更新已有公众号草稿时，只执行上述限定的更新及校验，不新建或公开发布。**

## 关键原则
- **画布统一 1080×1440（3:4），三平台一套卡片通用**。
- 封面随机两风格 + 随机淡背景，避免雷同；**只保留 1 张 `.claude` 原版文档页**。封面水印只放右上角 `@IT杨秀才`；原文页文档导航用网站名"秀才的进阶之路"。
- **后续讲解卡不能做网页截图式内页，也不能做纯文字点列卡**。必须图文并构、信息饱满、要点突出、逻辑清楚、层次清楚。
- **禁止模板偷懒**：不能把一篇文章的所有页面都塞进同一套「标题 + 若干圆角框 + 底部总结条」；视觉策划表与自动门禁是交付前置条件。
- **平台隔离**：通用图片、小红书/抖音文案不出现外部网址、微信号等引流；小绿书仅在正文结尾放指定学习网站介绍文章与两个项目的公众号链接，不混用小红书话题结尾，不退回纯文字网址。
- **正文严禁乱用引号**：生成 `copy.md` 后先校验正文段，命中引号就重写，不能带到发布页。
- 标题：封面保留原题，不虚构企业轮次；文字标题字段用"面试官：+精简题(≤20)"。
- **不主动发布/建草稿**：默认只交付图片和文案；明确授权的已有草稿更新按对应规则执行。
- 批量转化对每篇重复 1–6；`<slug>` 区分；风格随机自然多样。
